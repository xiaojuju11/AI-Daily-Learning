# campusTasks 需求规格（Requirements）

> 状态：**已澄清，待用户确认** — Specify + Clarify 阶段产出
> 最后更新：2026-09-19
> 本文件是需求真相来源（Single Source of Truth），实现以本文件为准。

---

## 1. 背景与问题

大学生在校期间同时面对多个来源的任务：课程作业、实验报告、大作业/论文、考试复习、社团活动、竞赛报名、实习兼职申请、生活事务（缴费、体检、宿舍事务）等。

这些信息目前分散在微信群、学习通/雨课堂通知、邮箱、纸质笔记和记忆里，由此产生四个具体痛点：

| 痛点 | 具体表现 |
| --- | --- |
| **看不见全貌** | 不知道「今天 / 这周到底还有什么没做」 |
| **漏交与赶工** | 截止时间靠记忆，临近才发现，只能临时赶工 |
| **优先级混乱** | 无法判断先做哪件，全凭当时感觉 |
| **无法回顾** | 学期结束后没有可回顾的完成记录 |

---

## 2. 目标用户

- **主要用户**：在校本科生 / 专科生，以「一个学期」为使用周期，日常在笔记本或手机浏览器中使用。
- **典型场景**：课后整理当天老师布置的任务；睡前列一遍明天要交的东西；周末规划下周安排。
- **非目标用户**：教师端（布置/批改作业）、班委/团队协作场景、学校教务系统管理员。

---

## 3. 用户目标（怎样才算「好用」）

1. 打开页面 3 秒内就知道：**今天到期什么、什么已经逾期、最近三天要交什么**。
2. **3 步内录入一条任务**：打开 → 填标题和截止时间 → 保存。
3. 完成后打勾即从待办中消失，可在「已完成」中回看。
4. 关闭浏览器或刷新后**数据不丢失**。

---

## 4. 范围

### 4.1 范围内（In Scope）

- 任务的**创建、编辑、删除、完成 / 取消完成**
- 任务字段：标题、所属课程、类型、截止时间、优先级、备注、状态
- 三种视图：**全部任务列表**、**按课程分组**、**看板（待办 / 进行中 / 已完成）**
- 时间状态视觉区分：已逾期、今天到期、未来 3 天内
- 筛选与搜索：按课程、类型、状态筛选；按关键词搜索标题与备注
- 本地数据持久化
- 数据导入 / 导出（JSON）
- 概览统计：待办数、今日到期数、逾期数、本周完成数
- 空状态引导与异常输入提示（全中文）

### 4.2 范围外（Out of Scope，本期明确不做）

- ❌ 用户账号、登录、云同步、多设备同步
- ❌ 多人协作、任务指派、班级共享
- ❌ 系统级推送通知、邮件 / 短信提醒
- ❌ 与教务系统、学习通、微信等第三方系统对接
- ❌ 原生 App（iOS / Android）
- ❌ 重复任务 / 周期性任务（如「每周三交作业」）

## 5. 功能需求

| FR-03 | 任务删除 | 删除前二次确认，防止误删 | 必须 |
| FR-04 | 完成 / 取消完成 | 一键切换完成状态，记录完成时间 | 必须 |
| FR-05 | 任务列表与排序 | 默认按截止时间升序；无截止时间的排最后 | 必须 |
| FR-06 | 按课程分组视图 | 以课程为分组，组内按截止时间排序 | 必须 |
| FR-07 | 看板视图 | 按状态分三列，可跨列移动任务 | 必须 |
| FR-08 | 时间状态标识 | 逾期 / 今天 / 3 天内 / 普通，四档视觉区分 | 必须 |

| FR-10 | 搜索 | 关键词匹配标题与备注 | 必须 |
| FR-11 | 概览统计 | 待办 / 今日到期 / 逾期 / 本周完成 四个数字 | 应该 |

## 6. 数据模型（草案）

```json
{
  "id": "唯一字符串",
  "title": "任务标题（必填）",
  "course": "所属课程 / 科目，可为空",
  "type": "作业 | 实验 | 考试 | 活动 | 其他",
  "dueAt": "截止时间，ISO 8601 字符串，可为空",
  "priority": "高 | 中 | 低",
  "status": "todo | doing | done",
  "note": "备注，可为空",
  "createdAt": "创建时间，ISO 8601 字符串",
  "completedAt": "完成时间，ISO 8601 字符串，未完成时为空"
}
```

存储整体结构：`{ "version": 1, "tasks": [ ... ] }`，便于日后升级数据结构。

## 7. 非功能需求

| 编号 | 需求 |
| --- | --- |
| NFR-01 | **免构建运行**：无需安装依赖、无需构建工具、无需联网、无需后端。通过本地静态服务器打开（推荐 `python3 -m http.server`）；Chrome / Edge 下双击 `index.html` 亦可运行 |
| NFR-02 | **数据自主**：数据仅保存在本机浏览器 localStorage，不上传任何服务器 |
| NFR-03 | **性能**：任务数 ≤ 500 条时，增删改查与视图切换无可感卡顿 |
| NFR-04 | **兼容**：Chrome / Edge / Safari 最新版正常使用；不支持 IE 及老旧内核 |
| NFR-05 | **可用性**：全中文界面；删除等破坏性操作有二次确认 |
| NFR-06 | **可访问性**：键盘可完成主要操作；状态不只用颜色表达（同时用文字/图标） |
| NFR-07 | **响应式**：桌面与手机窄屏（约 400px）均可正常使用 |
| NFR-08 | **零第三方依赖**：不使用任何框架、构建工具或 CDN，仅用原生 HTML / CSS / JavaScript |
| NFR-09 | **脚本加载方式**：使用经典 `<script src>`，禁止 ES Module（见 9.1 节原因） |
| NFR-10 | **代码可读性**：`js/app.js` 按职责分区并加中文注释，便于教学阅读与逐块讲解 |

## 8. 验收标准

> 验收标准必须是**可实际动手验证**的，不接受「页面能打开」这类模糊表述。

| 编号 | 验收标准 |
| --- | --- |
| AC-01 | 填写标题与截止时间后保存，任务出现在列表中的正确排序位置 |
| AC-02 | 标题为空时无法保存，并显示中文提示文案 |
| AC-03 | 勾选完成后任务标记为已完成并离开待办列表；取消勾选可恢复原状 |
| AC-04 | 逾期任务显示「已逾期 N 天」，今日到期显示「今天到期」，3 天内显示剩余天数，且样式与普通任务明显可区分 |
| AC-05 | 列表默认按截止时间升序，无截止时间的任务排在最后 |
| AC-06 | 切换到「按课程」视图后，任务按课程名分组，组内按截止时间排序 |
| AC-07 | 切换到看板视图后按状态分三列展示；跨列移动任务后其状态被正确更新 |
| AC-08 | 选择课程 / 类型 / 状态筛选后列表只剩匹配任务；搜索关键词能匹配标题与备注 |
| AC-09 | 刷新页面后，所有任务及其完成状态完整保留 |
| AC-10 | 导出 JSON 文件后重新导入，数据与导出前完全一致（含 id 与完成状态） |
| AC-11 | 概览中的待办 / 今日到期 / 逾期 / 本周完成数字与实际任务一致 |
| AC-12 | 删除任务需二次确认；确认后该任务从列表与统计中消失 |
| AC-13 | 无任何任务时显示中文引导内容，而不是空白页或报错 |
| AC-14 | 导入格式错误或损坏的 JSON 时显示中文错误提示，且现有数据不被破坏 |
| AC-15 | 窗口缩到手机宽度（约 400px）时，内容不横向溢出，核心操作仍可完成 |
| AC-16 | 已完成任务的时间徽章显示「已完成」而非「已逾期 N 天」，其视觉样式与四档进行中状态均不相同；截止时间仍可见 |
| AC-17 | 打开编辑弹窗时表单回填该任务的现有值；改标题与截止时间后保存，列表位置随之更新，且 `id` 与 `createdAt` 保持不变；取消编辑不改动任何数据 |
| AC-18 | 注入 500 条任务后，列表 / 分组 / 看板三种视图的渲染、筛选与关键词搜索均在 400ms 内完成，无可感卡顿 |
| AC-19 | 仅用键盘（Tab 移动焦点 + Enter/Space 激活）即可完成「新建任务 → 保存 → 勾选完成」全流程，且每个获得焦点的元素都有可见焦点环 |

> **AC-17 ~ AC-19 的由来**：Converge 阶段逐条审计规格时发现，FR-02（编辑任务）、NFR-03（性能）、NFR-06（可访问性）三项**有实现但无任何验收标准覆盖**——即"写了要做，却没人管做没做"。按 SDD 要求补入判定依据，而非默认它们没问题。

## 9. 澄清结论（Clarify）

> 用户已于 2026-09-19 确认，以下为**已定稿决策**，Plan / Tasks / Implement 阶段不得自行更改。

| 编号 | 问题 | **最终决定** | 来源 |
| --- | --- | --- | --- |
| Q1 | 交付形态 | **多文件纯前端**：`index.html` + `css/style.css` + `js/app.js`，原生三件套、0 依赖、0 后端，数据存 localStorage | 用户选定 |
| Q2 | 任务字段 | **完整字段**：标题、课程、类型、截止时间、优先级、备注、状态（详见第 6 节） | 用户选定 |
| Q3 | 视图形态 | **列表 + 按课程分组 + 看板**，三种视图 | 用户选定 |
| Q4 | 提醒方式 | **页面内高亮 + 概览统计**，不申请浏览器通知权限 | 用户选定 |
| Q5 | 示例数据 | **不预置**，首次打开仅显示空状态引导（用户可自行导入 JSON 体验） | 默认采纳 |
| Q6 | 浏览器兼容 | 仅需支持**现代浏览器**（Chrome / Edge / Safari 最新版），不支持 IE 及老旧内核 | 默认采纳 |

### 9.1 由 Q1 引出的一条技术约束（重要）

选择「多文件纯前端」意味着代码拆成 `html` / `css` / `js` 三类文件。经评估，这带来一条**必须写进规格**的约束：

> **必须使用经典 `<script src="js/app.js">` 标签，不得使用 ES Module（`import` / `export` / `type="module"`）。**

原因：ES Module 在 `file://` 协议下会被浏览器的同源策略拦截（CORS 报错），页面直接白屏。经典 `<script>` 标签没有这个限制。

由此，运行方式定为（两条路径都可，优先第一条）：

| 方式 | 命令 | 适用 |
| --- | --- | --- |
| **推荐**：本地静态服务器 | 在项目目录执行 `python3 -m http.server 8000`，浏览器访问 `http://localhost:8000` | 所有现代浏览器，含 Safari |
| 备选：直接双击 | 双击 `index.html` | Chrome / Edge 可用；**Safari 在 `file://` 下可能禁用 localStorage**，不保证数据保存 |

> 因此 NFR-01 已由「双击即可用」修正为「免构建运行」，见第 7 节。

## 10. 术语表

| 术语 | 含义 |
| --- | --- |
| 任务（Task） | 一条待办事项，本项目的核心数据单位 |
| 课程（Course） | 任务所属的科目归类，如「数据结构」「大学英语」 |
| 截止时间（dueAt） | 任务必须完成的时间点 |
| 时间状态 | 由截止时间与当前时间比较得出的四档标识：已逾期 / 今天到期 / 即将到期（3 天内）/ 普通 |
| 看板（Board） | 按状态分列展示任务的视图形式 |
