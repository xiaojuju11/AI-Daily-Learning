## 历史记录

### 2026-09-19 — 为 Task 增加 location 字段

- 决策：在 `Task` 数据模型中加入 `location` 字段（字符串，可为空），用于记录考试、活动等地点。
- 原因：`docs/product.md` 要求"考试：作为任务分类，可记录考试时间与地点"，但原 `docs/architecture.md` 的 Task 模型中没有承载地点的字段（考试时间可由 `due` 承载，地点无处安放）。两份已确认文档存在冲突，按产品需求补齐字段。
- 考虑过的备选方案：(a) 把考试地点写进 `note` 备注——不需要改模型，但结构化信息退化为自由文本，无法单独展示或筛选；(b) 删除产品文档中"可记录地点"的要求——缩小已确认的需求范围。选择新增字段。
- 影响范围：`docs/architecture.md` 的数据模型与 `app.js` 的 `normalizeTask` / 任务表单 / 任务卡片渲染。`note` 字段保持不变，仍用于自由备注。
- 状态：已确认

### 2026-09-19 — 多人协作与小组作业降级为本期不做

- 决策：本期不实现多人协作。"小组作业"仅通过任务的所属课程与分类字段，做单人视角的整理。
- 原因：用户第 6 题回答"其他需要"，其中包含小组作业协作；但真实协作需要多用户体系与服务端，与已确认的"不做账号、无后端"直接冲突。
- 考虑过的备选方案：只读分享链接（需服务端）；本地导出 JSON 互相传递（非实时，体验差）。
- 影响范围：`docs/product.md` 的"本期不做"。若后续要求真实协作，必须先推翻"不做账号体系"这一决定。
- 状态：待确认

### 2026-09-19 — 本期功能范围：任务、课程与校园分类

- 决策：用户将任务的字段、操作与视图授权 AI 决定，据此确定本期范围为——任务 CRUD 与完成标记；字段含标题、所属课程、分类、截止日期、优先级、备注；分类含作业/考试/实验/社团/个人/其他；视图含列表、今日/本周/逾期概览、按课程与分类与状态筛选、排序与标题搜索；校园数据含课程管理与周课表。
- 原因：用户核心诉求是"统一的清单"，并明确表示字段与视图细节由 AI 决定。范围需体现"校园"定位，同时与"无账号、无后端"的约束相容。
- 考虑过的备选方案：(a) 只做最简任务 CRUD，不含课程与课表；(b) 扩展做完整课程表 + 成绩管理 + 社团活动管理。选 (a) 体现不出校园定位，选 (b) 超出单机无账号形态的必要范围。
- 影响范围：`docs/product.md` 的功能范围与验收标准；`docs/architecture.md` 的数据模型（新增 Course 实体）；后续全部实现工作。
- 状态：已确认

### 2026-09-19 — 不做提醒与通知

- 决策：本期不实现任何提醒、推送或通知功能。
- 原因：用户明确回答"不要提醒通知"。
- 考虑过的备选方案：用浏览器 Notification API 做定时提醒；打开页面时高亮逾期任务。后者属于界面呈现而非通知，保留在"已逾期"概览中。
- 影响范围：无需申请通知权限，无后台定时逻辑；"已逾期"仅作为清单内的视觉提示。
- 状态：已确认

### 2026-09-19 — 不做账号体系，数据存浏览器本地

- 决策：不做注册、登录与多设备同步；数据持久化在浏览器本地存储。
- 原因：用户明确回答"不做"。这使项目保持纯前端、无后端、无数据库。
- 考虑过的备选方案：自建后端与数据库做账号同步；用第三方后端服务（如 Supabase）做免运维同步。两者都引入服务依赖与部署成本，与本期"打开就能用"的定位不符。
- 影响范围：`docs/architecture.md` 的持久化方案；数据仅存在于当前浏览器，清除浏览器数据会丢失，且不跨设备。
- 状态：已确认

### 2026-09-19 — 采用纯前端无构建的网页形态

- 决策：CampusTask 做成网页，用原生 HTML/CSS/JavaScript 实现，不使用框架、不引入构建工具与 npm 依赖、不用后端，直接用浏览器打开 `index.html` 即可运行。
- 原因：用户选择"网页"形态且不做账号，纯前端即可满足；与本仓库既有 demo（`demo-01`、`demo-02`）的无构建约定一致，离线可用。
- 考虑过的备选方案：React + Vite（需 npm 安装与构建）；Vue 单文件组件（同样需构建）；引入 CDN 版框架（离线不可用，且引入外部依赖）。
- 影响范围：`docs/architecture.md` 的全部技术约束；项目结构固定为 `index.html` / `styles.css` / `app.js`；后续实现不得引入构建步骤。
- 状态：已确认
