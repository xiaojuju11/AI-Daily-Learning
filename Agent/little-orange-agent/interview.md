# 面试官：你是怎么处理死循环的？
 - 怎么判断的：同一个工具名传入同相同的参数，以及它的执行结果一直都没有新的进展，这以这种模式，这种情况下出现了多次原地踏步的这种情况下。我认为它是到死循环了。

 - 怎么应对的：我就是拿文件名加参数和工具的执行结果，来用哈希算法加密生成一个工具指纹。 然后存放到一个数组当中，在数组里面去判断数组当中是否出现了这个工具指纹，当每一次循环开始的时候。我都会去判断当前大模型说要调用的那个工具和之前已经存好的那个数组里面的那些个工具指纹是否存在重复？如果存在重复的话，重复的次数是否达到了阈值？比如说我设计的是达到了 5 次，则做警告，生成一个警告提示词，注入到大模型的上下文当中去，让大模型知道。达到了 8 次，我就直接垄断，让之当前这次循环停掉，对吧？达到了 10 次也是直接垄断。


# 面试官：你是怎么处理API容错的？
 - 什么情况需要重试：首先我会对 API 返回的错误做分类归一化，区分可重试错误和不可重试错误。像网络波动、服务临时过载这类可重试错误才会触发重试；参数错误、鉴权失败这类不可重试错误，直接终止请求，不重试。

 - 怎么重试的：重试的时候，我设置了最大重试次数，比如最多重试 3 次。重试等待时间采用**指数退避加上随机抖动**策略，失败次数越多，等待时间指数增长，同时增加 ±25% 随机抖动，避免大量请求同时重试引发惊群效应。

 - 超出重试次数后，怎么处理的：如果重试耗尽，达到最大重试次数之后，当前版本会打印错误日志并直接抛出报错。在方案设计上我考虑了模型降级，也就是切换备选模型，不过这个功能当前版本还没有实现，计划放到下一版本迭代开发。
