# 阶段 3：Context Engineering（持续记录与可交接）

这一阶段演示的不是“把完整需求预先交给 AI”，而是将开发中产生的产品方案、技术约束、关键决定和进度持续写入项目。聊天记录会结束，项目文档不会；新会话的 AI 也能接手。

## 目录结构

```text
AGENTS.md                 # 工作流指针：何时读什么、何时更新什么
docs/
  product.md              # 产品方案与验收标准
  architecture.md         # 技术、结构、数据与约束
  decisions.md            # 已确认的关键决定与理由
  handoff.md              # 每轮结束必写的交接记录
```

四份文档都从空白结构模板开始。课堂中不要预先填 CampusTask 内容；让 AI 在对话中创建项目记忆。

## 课堂演示流程

1. 在新的空项目目录中复制本文件夹的全部内容。
2. 在新的 AI 会话中打开该项目。
3. 只复制下面一句话：

```text
我想做一个给大学生使用的校园任务管理器，项目叫 CampusTask。
```

预期现象：AI 先读 `AGENTS.md` 和四份文档，再将项目想法整理进 `docs/product.md`，提出必要澄清问题；它不应立即编写业务代码。

## 后续课堂指令

### 补充或改变需求

```text
补充需求：任务需要标题、课程、分类、截止日期和高/中/低优先级；用户要能创建、编辑、删除、标记完成，并按课程和完成状态筛选。请先更新项目文档，再告诉我还需要确认什么。
```

### 请求 AI 开始实施

```text
这些需求我确认了。请阅读项目文档，说明当前交接状态与实施范围；更新必要的技术和决策记录后，再开始实现。结束时必须写好交接记录。
```

### 要求一次明确交接

```text
现在停止当前工作，完成一次正式交接：更新 docs/handoff.md，并告诉下一位 AI 必须先读什么、当前完成到哪里、下一步具体做什么。
```

### 用新 AI 会话接手

在另一个新会话中，只复制：

```text
请阅读 AGENTS.md 及 docs/product.md、docs/architecture.md、docs/decisions.md、docs/handoff.md，接手这个项目。先用简短中文说明当前状态、未决问题和下一步；不要立刻改代码。
```

## 要向学生强调的区别

| 方式 | AI 的主要依据 | 跨会话后会怎样 |
| --- | --- | --- |
| Structured Prompt | 一次对话中的完整提示词 | 聊天上下文丢失后，关键信息容易丢失 |
| Context Engineering | 项目内持续更新的文档 | 新 AI 先读文档，就能恢复项目状态并继续 |

核心结论：**Context Engineering 不是多写几份说明，而是把对话中不断产生的项目知识，变成 AI 每次工作都能读取、更新和交接的外部记忆。**
