# AI写功能老是有bug，产出不可控，怎么办？
- Agent的产出，缺少一套自动把关的机制

- 产品产出不可控的两个问题：
1. 产出的时候没有人给它踩刹车
2. 产出之后没有东西自动验收



# Agent天生就会过度设计
agent在开发时相当于把第二系统效应拉满了

所以我们要让AI学会做减法：
1. 派活的时候就要要求最小实现。
  prompt:（用最简单的实现方式，不要考虑本次需求之外的扩展功能，能用现有的依赖就不要造轮子）

2. 事后让它自己做减法。
  在一轮功能跑通之后，追加一轮：”这段实现里，哪些代码时可以删掉的？哪些抽象是以本次需求用不到的？“

3. 把规则固化到AGENTS.md。
  - "优先使用项目现有的工具函数和依赖"
  - "不要为单一实现引入接口抽象"
  - xxxxxx

- 以上三种方法可以管住AI的 “多写”， 但是管不住AI的 “写错”
 
# 给产出建一个机器可以验证的闭环
- review中间层：虽然Agent产品已经帮我们做了一部分，但是中间层里面的多数操作还是需要人来完成的。

- 能被机器自动感知并拦截的错误，就永远不该消耗你的注意力
 1. typecheck 类型检查
 2. lint 代码规范检查
 3. unit test 单元测试
 4. 构建(build)
 

## hooks: 让闭环必然发生
  比如：编辑后自动lint

## UI视觉层
  想办法让Agent自己打开浏览器，截图看自己产出的效果发现不对再改


## 质检标准本身
  ```
  不要出现超过 500 行的模块，超了必须拆
  不要用 emoji 当图标，图标一律用项目的 icon 组件
  不要新增重复的工具函数，写之前先搜一遍现有代码
  不要吞错误的空 catch，要么处理要么往上抛
  新增接口必须有错误处理和参数校验
  涉及用户输入的地方必须考虑 XSS 工具
  ```
