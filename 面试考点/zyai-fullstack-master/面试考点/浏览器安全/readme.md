# 浏览器网络安全
1. XSS攻击
 cross-site-scripting 跨站脚本攻击，黑客在网页中嵌入恶意脚本，用户在访问该网页时，会执行该脚本，导致用户信息泄露
  - 脚本是怎么被注入的？
    - 1. 反射型XSS攻击
      - 用户在不知情的情况下，将恶意脚本作为参数传递给网站请求，网站在返回响应时，会将该脚本嵌入到响应中，用户在访问该响应时，会执行该脚本，导致用户信息泄露
      
    - 2. 存储型XSS攻击
      - 攻击者在网页中嵌入恶意脚本，用户在访问该网页时，会执行该脚本，导致用户信息泄露
      
    - 3. DOM型XSS攻击
      - 劫持 web 资源，篡改 web 页面

- 阻止XSS攻击
  - 1. 关键字符转译或者过滤
    - 将用户输入的字符串中的关键字符（如 < 、 > 、 & 、 " 、 ' 等）进行转译，防止被浏览器解析为 HTML 标签

  - 2. CSP
    - Content Security Policy 内容安全策略，是一种用于限制浏览器加载的资源的机制，可以防止 XHR 请求加载的资源被加载到页面中

  - 3. HttpOnly
    - HttpOnly 防止 cookies 被 JavaScript 访问，防止 XSS 攻击





2. CSRF攻击
 cross-site-request-forgery 跨站请求伪造攻击，黑客在用户不知情的情况下，将用户在网站上的操作（如登录、购买商品等）作为参数传递给网站请求，网站在返回响应时，会将该操作作为用户操作，导致用户信息泄露
  - 1. 自动发起GET请求

  - 2. 自动发起POST请求


- 阻止CSRF攻击
  - 1. 利用好 sameSite 属性
    - sameSite 属性是一种用于限制 cookies 跨域请求的机制，可以防止 CSRF 攻击
    - 可以在请求头中添加 sameSite=Strict 来限制 cookies 跨域请求

  - CSRF 令牌
    - CSRF 令牌是一种用于防止 CSRF 攻击的机制，可以在请求中添加一个随机数，网站在返回响应时，会将该随机数嵌入到响应中，用户在访问该响应时，会将该随机数作为参数传递给网站请求，网站在返回响应时，会将该随机数作为用户操作，导致用户信息泄露
    - 可以在请求头中添加 sameSite=Strict 来限制 cookies 跨域请求



# DDos攻击
 denial-of-service 攻击，是一种通过向目标服务器发送大量请求，导致服务器无法正常响应，从而影响正常用户的使用
 
 1. 防火墙
    - 防火墙是一种用于过滤网络流量的机制，可以防止 DDos 攻击
    - 可以在服务器端部署防火墙，对进入服务器的流量进行过滤，只允许合法流量流量进入服务器

 2. 负载均衡
    - 负载均衡是一种用于将流量分发到多个服务器的机制，可以防止 DDos 攻击
    - 可以在服务器端部署负载均衡器，对进入服务器的流量进行分发，将流量分发到多个服务器，从而防止 DDos 攻击
