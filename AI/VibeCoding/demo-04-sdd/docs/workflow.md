# SDD 教学工作流说明

## 目的

该模板用来演示：用户的一句话想法不会直接变成一堆代码。AI 先把不清晰的想法转为规格，再把规格转为计划和任务，最后用验收让结果持续向规格收敛。

## 每个阶段应产出的内容

| 阶段 | 文件 | 产出 | 允许写业务代码？ |
| --- | --- | --- | --- |
| Specify | `spec/requirements.md` | 用户、问题、范围、功能、验收标准 | 否 |
| Clarify | `spec/requirements.md` | 未决问题与确认后的决定 | 否 |
| Plan | `spec/plan.md` | 架构、文件职责、流程、风险与验证 | 否 |
| Tasks | `spec/tasks.md` | 按顺序、可验证的实施清单 | 否 |
| Implement | 产品源文件 + `spec/tasks.md` | 已实施并验证的功能 | 是 |
| Converge | `spec/convergence-report.md` | 验收证据、缺陷、修复与复验 | 是（只为修复偏差） |

## 澄清问题的原则

只问会实质影响产品、实现或验收的问题；优先问目标用户、核心流程、数据是否保留、边界、异常情况和成功标准。每个问题应包含推荐默认值，方便课堂快速推进。

## 收敛的定义

“页面能打开”不是完成。完成指：需求规格中的每项验收标准均有实际验证证据；若发现偏差，修复后重新验证受影响项目。
