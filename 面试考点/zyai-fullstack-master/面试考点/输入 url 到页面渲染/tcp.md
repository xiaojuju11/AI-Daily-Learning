# TCP
- 约定了资源应该处理成数据包的样子进行传输

- 每一个数据包有 头部
  1. Sequence Number: 序列号，用来标识数据包的顺序
  2. Acknowledgment Number: 确认号，用来标识已经收到的数据包的顺序
  3. Window Size: 窗口大小，用来标识接收端可以接收的数据包的大小
  4. 标识符：
    1. SYN: 同步标志位，用来标识连接请求
    2. ACK: 确认标志位，用来标识确认收到的数据包
    3. FIN: 结束标志位，用来标识连接结束


# 三次握手
1. 客户端向服务器端发送一个 SYN 包，用来请求建立连接  -- 客户端进入 SYN_SENT 状态
2. 服务器端向客户端发送一个 SYN-ACK 包，用来确认连接请求(同意应答，和连接请求)  -- 服务器端进入 SYN_RECEIVED 状态
3. 客户端向服务器端发送一个 ACK 包，用来确认服务器端的确认  -- 客户端进入 ESTABLISHED 状态


# 为什么一定需要三次握手？两次行不行
- 三次握手可以确保双方都知道对方的存在，并且都同意建立连接
- 两次握手不能确保双方都知道对方的存在，也不能确保双方都同意建立连接



# 四次挥手
1. 客户端向服务器端发送一个 FIN 包，用来请求断开连接  -- 客户端进入 FIN_WAIT_1 状态
2. 服务器端向客户端发送一个 ACK 包，用来确认断开请求  -- 服务器端进入 CLOSE_WAIT 状态
3. 服务器端向客户端发送一个 FIN 包，用来请求断开连接  -- 服务器端进入 LAST_ACK 状态
4. 客户端向服务器端发送一个 ACK 包，用来确认断开请求  -- 客户端进入 TIME_WAIT 状态 (2MSL)


# 特点
1. 可靠传输：TCP 确保数据的可靠传输，通过序列号、确认号和重传机制实现。
2. 有序传输：TCP 按照发送顺序将数据分块传输，接收端按照序列号 reassemble 数据。
3. 流量控制：TCP 利用窗口大小机制实现流量控制，防止发送端发送过快导致接收端缓冲区溢出。
4. 拥塞控制：TCP 利用拥塞窗口机制实现拥塞控制，避免网络拥塞。 (网络环境不好，发包速度慢)(慢启动)
