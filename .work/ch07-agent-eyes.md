# 第 7 章 给 Agent 一双眼睛

> 测试全绿不代表页面能看。代码层管不到的东西，得让它自己打开浏览器看。

## 为什么需要它

单元测试断言的是"这个按钮的 onClick 被调用了"，不是"这个按钮有没有被弹窗盖住"。

视觉和交互的错，天然在测试覆盖之外：布局塌了、文字溢出、Toast 挡住提交按钮、深色模式下字看不见。这些错上线后用户第一眼就发现，而你的 CI 一片绿。

## 术语表

| 术语 | 人话 | 类比 |
| --- | --- | --- |
| 浏览器自动化 | 用代码驱动浏览器：打开、点、填、截图 | 一个不知疲倦的测试员 |
| 视觉回归 | 把这次截图和上一版对比，找出差异 | 装修前后拍对比照 |
| computer use | 让模型直接操作桌面 | 网页之外的备用手段 |

## 两类工具，别混用

很多人以为"接个浏览器工具"就够了，其实要分两种能力：

| 类型 | 干什么 | 典型工具 |
| --- | --- | --- |
| 操作型 | 打开页面、点按钮、填表单、截图、读页面结构 | Playwright、agent-browser、Playwright MCP |
| 排查型 | 页面不对时进去查为什么：console 报错、network 请求、performance | Chrome DevTools MCP |

操作型负责"复现"，排查型负责"定位原因"。

只给操作型，你会得到"点完了，页面白了"这种没有信息量的结论。两个都给，它才能自己走完一条链：复现 → 看 console → 发现接口 500 → 回头改代码。

## 怎么让它看：给一条具体路径

别让它"随便看看"。一条能直接复制的提示词：

```text
打开 http://localhost:3000/login
输入错误密码，点登录，等 2 秒
截图，然后回答三个问题：
1. 错误提示出现了吗？在页面哪个位置？
2. 提示文字和输入框有遮挡或重叠吗？
3. 这个提示的间距，和项目里的设计 token 一致吗？
如果不对，直接改，改完再截一次图给我看。
```

最后那句"改完再截一次图"是关键：它把"看"变成闭环，而不是一份描述。

## 从"看一眼"到"每次都看"：回归测试平台

单次截图是救火。要防回归，得把这件事变成一条命令。

下面这份规格可以直接扔给 Agent，让它给你搭一个最小的平台（只用 Node 标准库，不引框架）：

```text
做一个最小的 UI 回归测试平台：

1. 服务端 server.mjs
   - 读 e2e/*.spec.ts 里所有 test 名字 + cases.json 里的分组和优先级，
     合成一份用例清单
   - POST /api/run：起一个 playwright 子进程跑测试，
     支持 -g 只跑某个分组，实时汇报进度
   - 跑完解析 JSON 报告，把每条失败用例和对应的 HTML 报告（截图/录像）
     关联起来，结果存进 runs.json

2. 前端
   - 左边用例清单，按分组展示，能单选某个分组重跑
   - 右边是最新一轮的结果 + 历史记录
   - 风格：白底、克制的灰阶，状态色只给红和绿

完成后自己跑起来，用浏览器截图确认能用。
```

为什么是这几条：

- **用例清单从 spec 文件读**：测试和平台不重复维护两份列表；
- **`-g` 分组**：跑全量太慢，日常只跑相关分组；
- **失败关联 HTML 报告**：截图和录像比日志快十倍；
- **`runs.json` 存历史**：能看出"这条是用例不稳还是真的坏了"。

## 够不到的地方

浏览器能覆盖网页，覆盖不了桌面应用、系统弹窗、外部客户端。这种时候用 **computer use** 兜底——让模型直接操作鼠标键盘，看屏幕截图判断状态。

它是最后的兜底，不是首选：慢、贵、不稳定。能用选择器定位的，别用坐标点击。

## 翻车现场

::: warning 测试全绿，按钮点不到
提交流程的单测、类型检查、构建全过。上线后用户反馈"提交按钮点不动"。

原因是新加的一个固定定位提示条，正好压在按钮上方。DOM 里按钮还在，`onClick` 也正常，只是被盖住了。

补上截图检查后，这类问题第一次出现就会被看见——图里那个按钮确实灰了一块。
:::

## 一个判断标准

问自己：**这个错误，如果我给它一张截图，它能不能自己发现？**

能，就值得接浏览器工具；不能（比如"这个交互手感对不对"），还是得你自己看。

## 自测三问

1. 你的项目里"测试全绿但页面有问题"这类 bug，最近一次是什么？一张截图能不能提前发现？
2. 操作型和排查型工具，你缺哪一个？缺了会卡在哪一步？
3. 视觉回归的基线由谁更新？如果没人更新，它会变成什么？
