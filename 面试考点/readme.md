# hooks:
- useEffect: useeffect是react中的一个hook函数，它可以接收两个参数，第一个参数可以是一个回调函数，这个函数在页面加载完毕后后执行，第二个参数是一个数组，数组值必须是响应式变量，当其中响应式变量变更后，导致回调函数再次触发。传入的回调函数可以返回一个函数，这个函数将在组件卸载时触发
- useState:用来储存变量，里面的变量发生变化时，组件会重新渲染，导致组件的重新执行。
当他的变量放在 useEffect 中时，可能会形成闭包陷阱，导致useState值不变（因为useEffect会默认用一个变量/函数承接useState的值。解决方法：useState自带的((prev) => prev + 1)，或者在useEffect中第二个参数中使用useState的，然后返回一个函数让他在组件卸载时删除一个定时器），或者在外面创建一个新的函数体，用ref.current来承接这个函数，放进定时器里面，每次函数的那个引用地址不同，就能破除闭包陷阱
- useRef：（里面有个对象，current：值）
  1. 专门获取DOM结构
  2. 他创建出来的变量不会被组件的重新渲染所影响，所以可以用来存储一些持久化的数据。但是不会导致组件的重新渲染。

# react 工作原理
1. 将 jsx 代码进行编译，得到 虚拟 DOM 对象 （靠babel编译）
2. 遍历虚拟 DOM 对象，将对象中的 jsx 语法，特殊属性 替换成 js 语法和普通属性
3. 拿着被修改后的虚拟 DOM 对象，生成真实的DOM 结构， 调用 react 的 render 方法，将真实的DOM 结构渲染到html 中

# MVC 和 MVVM 的区别
MVC 是把代码分成模型、视图、控制器三部分，视图和模型不直接通信，都由控制器来调度。缺点是控制器容易臃肿，逻辑集中。
MVVM 是 MVC 的升级版，是一种强大的软件设计模式，它通过分离UI逻辑与业务逻辑、实现数据的双向绑定和重用视图逻辑等方式，提高了应用程序的可维护性、可测试性和可重用性。
react 也是MVVM ，但是是单向数据流，又有点违背了MVVM的设计理念，不像vue是双向数据流，React虽然不直接遵循MVVM模式，但它通过组件化和状态管理（如Redux或Context API）用第三方库等实现了类似的效果。
数据只能从组件的父级传递给子级，子组件不能改（官方定为了只读属性，如果要改的话就会导致数据流不可控）

# promise 实现原理
- promise 内部维护了一个状态，准备状态，成功状态，失败状态，我们在函数内部返回一个 promise 对象，默认得到的是准备状态，当用户手动调用 resolve 函数的时候，那么状态就会变成成功状态，当用户手动调用 reject 函数的时候，那么状态就会变成失败状态。状态一旦修改，就不能再撤回。只有当状态变为成功状态的时候，.then 里面的第一个回调才会被触发，如果变成失败的话，第二个回调会触发，当然catch也会触发，它与.then的第二个回调效果是一样的，finally是指不管成功还是失败都会执行的。
- 什么情况下用到了promise
接口请求
比如一个函数的执行需要依赖另一个函数的执行结果
- 静态方法
Promise.resolve() 快速返回一个成功状态的 promise 对象
Promise.reject() 快速返回一个失败状态的 promise 对象
Promise.all([p1,p2,p3])所有的 promise 都成功了，按顺序返回结果（同时请求多个接口，全部拿到再渲染）
Promise.race([p1,p2,p3])谁快，就返回谁的结果不管成功失败（接口超时控制）
Promise.allSettled()不管成功失败，全部执行完 ，返回每个结果的状态
Promise.any() 只要有一个成功了，就成功了，返回第一个成功的结果

# 输入url到页面渲染的过程 
DNS解析 =》建立TCP连接 =》发送HTTP请求 =》TCP断开连接 =》浏览器解析HTML成DOM树 =》浏览器解析CSS成CSSOM树 =》合并DOM树和CSSOM生成渲染树 =》 计算页面布局 （回流）=》 渲染页面(GPU) （重绘） 
- 发生回流的场景：页面元素的几何属性发生变化时，浏览器会重新计算元素的位置和大小，这个过程称为回流。
- 重绘发生的场景：页面元素的外观属性发生变化时，浏览器会重新绘制元素，这个过程称为重绘。
- 浏览器的优化机制：
 由于每一次回流都会造成额外的计算消耗，所以浏览器会维护一个优化队列。将回流行为存放在队列中，直到一定时间后，或者达到阈值后，浏览器会一次性执行队列中的回流行为。
物理层，网络链路层，网络层，运输层，会话层，表示层，应用层
TCP:可靠有序，流量控制，拥塞控制
队头阻塞问题： 当一个 TCP 连接中，某个请求的响应延迟了， 其他请求的响应也会被阻塞
  1. 只保留一个 TCP 连接， 其他请求都在这个连接上发送
  2. 将该TCP 连接中的多个请求切片：每个请求片段还可以打上加急标签， 服务器可以根据标签，优先处理加急的请求
- 对称加密：客户端和服务端都知道一个密钥， 用这个密钥加密数据， 也用这个密钥解密数据。
- 非对称加密：客户端创建一个密钥，服务端创建一个公钥和一个私钥，服务端将公钥发送给客户端，客户端用公钥加密 密钥，传输给服务端，服务端用私钥解密密钥。


# GET 和 POST 请求
1. GET 的参数是添加在 url 上的，而 POST 的参数是添加在 request body 中的
2. GET 请求会被缓存，而 POST 请求不会被缓存
3. get 会留下浏览器历史记录，而 post 不会留下浏览器历史记录
4. get 请求参数不能超过 2048 字个字符，而 post 请求参数可以超过 2048 字个字符 
单纯获取数据没有敏感数据就用get请求，不要用post请求，不用传参就用get请求

- 超时重传
封装了一个超时重传的一个函数，里面引入了axios，所有的请求都是用这个发的，当请求超时了，会自动重发
> 是 TCP 实现可靠传输的关键机制。发送方发送数据后会启动超时计时器，如果在 RTO 时间内没收到 ACK，就认为报文丢失，重新发送。
因为网络延迟不固定，TCP 不会用固定超时，而是根据采样 RTT 动态计算平滑 RTT 和偏差，自适应调整 RTO。
实际重传有两种：一种是计时器到期的超时重传，另一种是收到 3 个重复 ACK 触发的快速重传，快速重传不用等超时，能更快恢复丢包，提升效率。

- 双token
后端返回一个access token和一个refresh token，短token 我设置了一天有效期，长token 我设置了七天有效期，当用户登录成功之后，前端拿到了后端返回的两个token，然后本地存储，在后续的请求当中，前端会将短token携带在请求头中发送给后端，后端校验，如果短token过期了，我再axios 响应拦截里面设置了401错误（短Token 失效），前端捕获到了这个错误，就会立即读取长token，再次向后端发请求并携带这个长token，让后端再次生成新的长token短token传回来给前端，并且将刚刚没有发送成功的请求再发送一次实现用户无感刷新

# webpack 构建原理 
- 是深度优先式的递归遍历去做依赖收集，然后将所有的依赖收集完之后，去生成抽象语法树，将抽象语法树里面的一些高版本的代码降级处理（babel 插件实现），处理成浏览器能兼容的版本，最后再生成成浏览器真实能执行的代码

# vite 构建原理
- 维护了一个node服务，默认向前端输出一个HTML文件，当浏览器在加载HTML文件的过程当中，碰到其他的依赖项的时候会转而向vite服务发请求，vite服务继续返回依赖项，以此类推。

# vite为什么这么快：
Vite 借助新版本浏览器可以读懂模块化语法的特点，将项目中的模块化引入统一以一个又一个http请求的方式响应给浏览器，这样做的好处就是省去了 Webpack 构建过程中递归做依赖收集的耗时步骤，又因为Vite是开发环境的工具，绝大多数情况下我们不用不考虑兼容性，不会有人开发时还用老版本的浏览器吧

null 是一个特殊的关键字表示一个空对象指针，可以用来赋值变量。（手动赋值）

# 浏览器缓存：
- 分为强缓存和协商缓存
强缓存是后端通过设置响应头里面的Cache-Control: max-age=86400 浏览器会将响应缓存起来，下次请求相同资源时直接从缓存中读取，不会向服务器发送请求。
协商缓存是通过设置响应头里面的Last-Modified    if-modified-since  资源最后修改时间戳
etag             if-none-match  哈希值，资源指纹 
强缓存过期了，浏览器会向服务器发送新请求带上上次的时间戳或则哈希值，服务器进行对比，请求头中的 `If-Modified-Since，if-none-match` 时间戳或则哈希值判断资源是否有更新
如果资源没有更新，服务器会返回 `304 Not Modified` 响应，从而让浏览器继续从缓存中读取资源
如果资源有更新，服务器会返回 `200 OK` 响应，浏览器会从响应体中读取资源

# 浏览器存储
- localStorage 本地存储，持久化存储，关闭浏览器后数据不会丢失 5MB
- sessionStorage 只在当前页面会话存储，关闭页面后数据会丢失 5MB
- cookie 有后端控制存储数据，可以设置过期时间
- indexedDB 存储量无穷大，时间可永久存储，通常作为客户端数据库

# LLM
大模型（LLM）是基于Transformer架构、靠海量数据训练、用概率预测下一个词来生成文本的深度学习系统

# function calling:
当大模型遇到回答不出来的问题或者未被训练过的内容时，我们可以给他封装一些工具函数，当遇到这些问题时就直接调用相应的工具函数来解决问题，得出结果后，再将得到的结果返回给大模型，由大模型返回出来

# MCP(model context protocol)
是一种协议，用于统一大模型和工具函数的交互。就像转接头一样，入口不同，出口不同，但是中间的处理过程是一致的。

# RAG(retrieval augmented generation)
一套体系，结合 信息检索 和 语言生成 的人工智能架构，通过将知识内容的文本转换成向量，存放在专门的向量数据库中。让大模型可以根据用户的问题，从向量数据库中检索出最相关的向量，从而生成符合用户需求的回答。
- 构建向量检索 
1. embedding 模型 来将文本转换成向量
2. 向量数据库 来存储向量  (vector database)
