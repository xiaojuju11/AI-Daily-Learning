## 3. 发现并修复的偏差

### 3.1 关键事实：三个真实缺陷全部躲过了「全绿」的测试

首次运行套件即 **16/17 通过**；修掉一个测试选择器 bug 后 **17/17 全绿、0 页面异常**。但随后看截图，发现 **3 个测试完全测不出来的真实缺陷**：

## 4. 方法论验证：为什么这一步不能省

本次收敛完整复现了 SDD 的核心主张，也复现了本项目历史上踩过的坑（记录于记忆 `verifying-browser-demos-via-cdp`）：

> **无效的 CSS 不会被报错，只会被静默丢弃；测试断言的是"元素存在"，而用户面对的是"看不看得见"。**

- 断言 `element.style.color` 会假绿 → 本次全部改用 `getComputedStyle()`
- 断言"元素可点击"也会假绿 → D-01 正是如此
- **截图不是最后手段，而是常规步骤** —— 三个真实缺陷全部由截图发现

本次还验证了另一条推论：

> **"测试全绿"的第三种失效方式是——测试压根没测那个需求。**

21 个用例全绿，但 `updateTask()` 从未被调用、500 条任务从未被渲染、Tab 键从未被按过。绿灯只覆盖它实际走过的路径；**没走过的路径，绿灯不代表任何东西**。这正是 §3.4 要做覆盖盲区审计的原因：不看"测试是否通过"，而看"规格里每一条，是否都有测试在管"。
