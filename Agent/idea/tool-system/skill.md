# Skills
与其教模型使用新的协议，不如让它使用它最擅长的能力---读文件


- 如果skills过错，比如 100+ 个skills, 不可能将所有的内容都塞进上下文

- 如何处理这种情况：采用三层渐进式的加载
  1. Frontmatter(永远都加载)
    每个skill.md 开头都有一段 YAML 格式的 Frontmatter
      ---
      name: weather-info
      description: 获取全球任意城市的实时天气信息和天气预报。当用户询问天气、温度、降雨、风速等气象信息时，使用此技能。
      version: 1.0.0
      author: Claude Code User
      ---
    
  2. 完整的内容（按需加载）
    只有当模型判断当前任务跟某个skill相关时，才会加载该skill的完整内容

  3. 引用文件（再按需加载）
    因为skills 文件夹下可以存在 scripts (可执行的脚本)、 references（参考文档） 等文件，这些文件不去主动加载，模型需要时采用 Read 工具来读取

# Skills vs MCP
1. MCP走的是 协议标准化 --- 定义一套通用协议，任何加客户端都能接入，好处是跨平台，坏处是协议本身也是占用Token开销的

2. Skills走的是 文件约定 --- 一个文件夹，一个md文件，几个脚本。好处是简单，轻量，模型天然会用读文件的能力，坏处是没有标准化的跨平台协议。


- skills 可以安装在claudeCode的全局，也可以放在由claudeCode管理的项目中

- MCP是能力，Skills是 知识+能力。

- MCP 和 Skills 不是竞争关系，而是合作关系，是分工系统--- Skills负责”知道怎么做“, MCP负责”实现它“

# 面试回答：
MCP 是一个 JSON‑RPC 协议，它定义了一套标准，目的是让各家公司、第三方开发的工具，可以顺畅接入各类 AI 产品。它就相当于充电线的万能转接头。

不同 AI 产品的工具对接接口标准各不相同。一个能在 Claude Code 调用的工具，很可能无法被 Codex 调用。MCP Server 就提供了一层套壳手段，以此保障工具函数的通用性。

MCP 有一个明显缺陷：会消耗大量 Token 上下文。接入的 MCP 服务一多，Agent 就可能自主执行很多你并没有要求的操作。一个 MCP 服务通常会附带 20 个左右工具，GitHub 官方的 MCP 服务甚至自带近 50 个工具。

不同 Agent 有不同的处理方案，Claude Code 采用的是**延迟加载**。

在 Claude Code 源码中，所有来自 MCP 服务的工具，都判定为用户安装的工具，统一标记为延迟加载。就连 Claude Code 的内置工具，也做了延迟标记。只有极少数高频常用工具，才会每次都带入对话上下文。

它依靠 Tool Search 机制实现：大模型接到任务，需要用到某工具时，才去检索该工具是否可用。如果不做延迟加载，全部工具都塞进上下文，上下文会直接溢出。

引入 Tool Search 之后整个流程发生变化。
旧流程：大模型收到任务，直接返回要调用的工具。
新流程：大模型收到任务，先发起工具检索，告知系统需要搜索可用工具来解决当前问题。

Tool Search 分为三层：精准匹配、模糊搜索、结果排序。检索到需要的工具函数之后，才调用执行，再把执行结果返回大模型。

还有一个问题：工具执行返回的输出体量可能非常大，如果全部直接丢回大模型，同样会造成上下文溢出。上下文存在上限，例如 256K、1M。

处理策略：不会把全部返回内容直接传给模型，设置大约 50K 的阈值。一旦输出超过阈值，就把完整结果写入本地磁盘，只把摘要和文件路径交给大模型。模型阅读摘要，如果信息不足，再通过路径读取完整文件。

MCP 还存在安全风险。会存在恶意 MCP 服务，可能窃取你的 Token。举个例子，浩泽曾遇到，在没有操作的情况下，Token 被大量消耗，产生 80 元账单。有可能是接入了恶意 MCP 服务，读取本地.env 文件里的 API 密钥。

遇到密钥被盗刷，要立刻作废旧 Token，重新生成新 Token，及时止损。

另外 MCP 具备一定复杂度，MCP 服务一般基于 Node 开发，每一个 MCP 服务都要独占一个端口和进程，会给设备带来额外性能开销。

接下来讲 Skill。
如果面试被问到什么是 Skill，只回答 “提示词” 是不够专业的。
Skill 可以理解为精装版提示词，有固定格式，必须包含 front‑meta 头部和主体内容。头部一般包含技能名称、描述、版本、作者等信息。

不同 Agent 支持的 Skill 字段不一样。部分 Agent 的 Skill 头部还可以写明依赖安装方式，例如 npm install、UV 环境、Node 环境。

Skill 不能做到跨所有 AI 产品通用，它缺少标准化协议。一份 Skill 在一个 Agent 可以正常工作，换到另一个 Agent 可能无法生效，部分字段不被识别。

Skill 的优势是极度简洁，本质就是格式化后的提示词，调用的是大模型读取文件的能力。模型原生读文件的能力，要强于调用 MCP Server。

MCP 出现时间比较晚，现有已训练完成的大模型，并没有充分学习 MCP 的使用范式。未来新模型会加入 MCP 相关训练，但即便模型熟悉 MCP，也无法消除 MCP 本身自带的各类缺陷。
