# 每日笔记

> 当天的素材，先原样扔在这儿。周末再决定哪些值得进书。

## 为什么单独一本书

稿子写得糙不是问题，**混进正式章节**才是问题。所以分两层：

| 层 | 位置 | 状态 | 要求 |
| --- | --- | --- | --- |
| 素材 | `docs/daily/` | 半成品 | 能看懂就行，允许语病和碎片 |
| 成书 | `docs/<书>/chNN-*.md` | 成品 | 有结构、有示例、有自测 |

## 每天两分钟

```bash
npm run new -- daily "2026-11-09" 2026-11-09
```

然后只填三格：**今天搞懂了什么 / 卡在哪 / 明天第一步**。

## 每周一次合并

周末打开 daily 目录，把同一主题的三五条笔记并成一章，搬进对应的书里。搬运时只做三件事：

1. 给秩序——按"为什么 / 怎么工作 / 怎么用"重排。
2. 补例子——素材里一般是结论，成书必须有能跑的代码。
3. 删废话——凡是"我觉得""大概"开头的，要么给证据，要么删。
