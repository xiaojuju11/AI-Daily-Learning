# Agents.md
是agent开机必读的文件


# Agents.md 是投入产出比最高的文件
1. agent每次启动都是失忆的状态
2. Agents.md 文件的影响覆盖范围是你跟agent的每一次交互


# 巨型文件是怎么崩坏的
1. 注意力稀释
  （1. 前沿模型大概能遵守150-200条指令）一旦超过这个范围，所有的规则遵守质量都会下降

2. 上下文腐烂
  代码天天在变，架构在演进，但是Agents.md文件的上下文没有变化

- 所以问题不是信息，是agent什么时候读信息，所以：
  1. 给agent制定约束，应该要目录式（渐进式披露）
    AGENTS.md (~100行)
      项目是什么 + 常用命令
      important: "认证相关 先读 docs/auth.md"
      important: "数据库相关 先读 docs/db.md"

  
- OpenAI的解法：
  将Agents.md控制在100行左右，主要是告诉agent，你需要知道的东西在哪里，真正的知识放在docs目录中（设计文档、架构文档、产品规则、安全规范等等）


# 一个好的Agents.md 长什么样
- Agents.md是一套层级系统，一共四个位置，作用范围也不同：
  1. ~/.codex/Agents.md 全局（比如：用户的偏好，用中文回复）

  2. 项目的根目录下的 Agents.md 当前项目的主战场，团队共享，应该提交到git仓库

  3. 项目子目录下的 Agents.md。前端项目一个Agents.md，后端项目一个Agents.md


- 三个维度：WHAT、WHY、HOW
  1. WHAT
    项目是什么 + 技术栈是什么 + 目录结构是什么

  2. WHY
    每个模块的职责，为什么选这个方案

  3. HOW
    怎么做测试，怎么打包构建，用什么包管理器

  

# 把Agents.md文件当成一个活文件要养护
1. 将 Agents.md 当错一个错题本，每次出现的翻车记录，都要写在Agents.md中

2. 定期做减法：每隔几周，就让Agent自己审查一遍这个文件，删除一些过期的信息，删除冗余的规则
