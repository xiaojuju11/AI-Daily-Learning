### 2026-09-19 — 实现 CampusTask 首版并通过端到端验证

- 本次目标：按 `docs/product.md` 的验收标准实现首版，并做真实浏览器验证。
- 当前阶段：开发中 → 首版完成。
- 已完成内容：
  - 新建 `index.html`、`styles.css`、`app.js`，沿用本仓库 demo-01/02 的无构建形态（原生 HTML/CSS/JS，`file://` 直接打开）。
  - 任务：创建 / 编辑 / 删除 / 标记完成，字段含标题、所属课程、分类、截止日期、优先级、地点、备注。
  - 视图：待办与已完成分区、今日 / 本周 / 已逾期 / 未完成四张概览卡片、按课程与分类与状态与优先级筛选、按截止日期与优先级与创建时间排序、按标题搜索。
  - 校园数据：课程管理（课程名、教师、地点、多个上课时间段）与周课表视图。
  - 持久化：`localStorage`（`campustask.tasks`、`campustask.courses`），含数据规范化与存储不可用时的降级提示。
  - 界面支持跟随系统的浅色 / 深色主题。
- 涉及文件：`index.html`、`styles.css`、`app.js`、`docs/product.md`、`docs/architecture.md`、`docs/decisions.md`、`docs/handoff.md`
- 验证与结果：
  - 用 headless Chrome + DevTools Protocol 写了端到端验收脚本（存放在项目外的临时目录 `/tmp/campustask-cdp/`，不污染交付物，也不引入任何 npm 依赖），**72 项断言全部通过**，覆盖 7 条验收标准，含刷新持久化、注入防护、异常输入与控制台无报错。
  - 另用截图逐屏人工核对了任务清单、周课表、课程管理、表单弹窗与深色主题。
- 本轮修复的两个真实缺陷（均已回归验证）：
  1. **表单被永久锁死**：`form.reset()` 不会清除 `setCustomValidity`。用户提交过一次空标题后，该输入框会一直处于无效状态，之后无论填什么都无法保存，只能刷新页面。已在打开弹窗时与用户输入时显式清除。
  2. **周课表布局完全错位**：课程块原先用 `grid-row` 定位，而 CSS Grid 的行号只接受整数，`grid-row: 2 / 3.667` 被浏览器静默丢弃并回退为自动放置，导致所有课程块堆在表格底部。已改为绝对定位 + 百分比换算，并在 `docs/architecture.md` 记为实现约束。
  - 值得记取的教训：缺陷 2 第一次测试没有抓到，因为断言读的是 `element.style.gridRow` 这个字符串本身。断言必须针对**真实渲染几何**（`getBoundingClientRect`），而不是自己写进去的值。
- 未决问题 / 风险 / 阻塞：
  - `docs/product.md` 待澄清问题第 1 条仍未确认："Notion"是指主要对标对象，还是"必须做对的点 = 比 Notion 更轻、免配置"。当前按后者实现。
  - `docs/decisions.md` 中"多人协作与小组作业降级为本期不做"仍是**待确认**状态。
  - 技术限制：同一天同一时段的两门课在课表上会互相重叠，未做分列排布。
  - 技术风险：`file://` 下浏览器可能清理 `localStorage`，且无导出功能兜底，数据有丢失可能。
- 下一步建议（按优先级）：
  1. 请用户在真实浏览器打开 `index.html` 验收，确认交互与视觉是否符合预期。
  2. 若需防数据丢失：增加"导出 / 导入 JSON"（纯前端，不违背无后端约束）。
  3. 若课表重叠影响使用：为同一时段的课程做并排分列。
  4. 明确上面两条待确认问题，据此更新 `docs/decisions.md`。
- 下次开始前必读或确认：`AGENTS.md`、`docs/product.md` 的验收标准与待澄清问题、`docs/architecture.md` 的实现约束（尤其是周课表定位方式）、本文件的"当前快照"。
